# RTL Chat Implementation Plan

**Goal:** A Firefox MV3 extension that gives Arabic text the right direction on AI chat
sites, ready to load from `about:debugging` and to submit to AMO as a listed add-on.

**Architecture:** One module (`src/direction.js`) decides which elements get a `dir`
attribute and which CSS a page gets. The content script wires it to the page and to
`storage.sync`; the background script inserts the CSS with `scripting.insertCSS` (immune
to the page's CSP) and keeps one registered content script in step with the host
permissions the user granted for extra sites. The popup only writes settings and asks
for or drops a host permission.

**Tech stack:** WebExtension Manifest V3, plain JavaScript, no dependencies, no build
step. Tests: `node --test` for pure logic, headless Firefox for real layout, and
`tests/live/` for the real sites.

**Spec:** `docs/superpowers/specs/2026-10-13-rtl-chat-design.md`

## Global constraints

- Public name **RTL Chat**, licence **MIT**.
- No dependencies in `package.json`. `web-ext` runs through `npx` only.
- No network requests, no remote code, no data collection
  (`data_collection_permissions.required = ["none"]`).
- Permissions: `storage`, `scripting`, `activeTab`; `host_permissions` for the hosts of
  the two supported sites only; everything else through `optional_host_permissions`.
- Desktop Firefox only, 142 or later.
- Code and math stay LTR in every mode.
- Site chrome (navigation, menus, toolbars) is never restyled, and the text alignment
  a site chose is never overridden, except in the cells of a right-to-left table.
- Nothing is published to AMO and the repository stays private.

## Review focus

1. **An Arabic sentence that opens with a Latin word**, and an English one with an
   Arabic word in it — direction follows the language most of the text is in.
2. **Streaming** — text that arrives node by node, or as characters added to a node
   already there, ends up with the direction it would have had arriving whole.
3. **Switching off** — every attribute the extension set is removed and a `dir` the
   site had is put back.
4. **A site that is already right-to-left** — Arabic text and an empty composer are
   not touched.
5. **Settings that are missing or malformed** in `storage.sync` — the extension falls
   back to automatic mode, enabled, instead of throwing.

Each is pinned by a check in `tests/unit.test.js` or `tests/browser/assertions.js`.

## How the direction is decided

`src/direction.js`, all on `globalThis.RTLChat`:

- `detectDirection(text) -> "rtl" | "ltr" | null` — right-to-left once 30% of the
  letters are; `null` for text with no letters.
- `collectTargets(root, site)` — the elements whose direction the extension decides,
  in document order:
  - **blocks** (`p`, headings, `blockquote`, `dd`, `dt`, `summary`, `figcaption`,
    `.whitespace-pre-wrap`, the site's `text`), unless a list item or cell holds them;
  - **containers** (`ul`, `ol`, `table`), unless the list carries an `aria-label`;
  - **inputs** (`textarea`, text inputs, editable elements, the site's `input`).

  Nothing inside code or math, and no block or container inside site chrome.
- `targetsAround(node, site)` — the targets a change at `node` can affect.
- `syncElement(el)` — judges the element's text (a field's value; otherwise its prose
  without code) and sets `dir` only when that differs from the direction the element
  already has. Marks it with `data-rtl-chat`, keeps a previous `dir` in
  `data-rtl-chat-orig`. Text with no letters: the element is restored.
- `syncIndent(list)` — flags with `data-rtl-chat-indent` a right-to-left list that has
  markers and is indented on the left alone.
- `settle(el, mode)`, `applyAll(root, site, mode)`, `clearDirections(root)`,
  `clearAll(root)`.
- `buildSheets(site, mode)` — two stylesheets:
  - author origin, with `!important`: code and math LTR; cells of a right-to-left
    table aligned to their start; the indent of flagged lists; an emptied field showing
    its placeholder in the site's direction; and, in forced mode only,
    `direction: rtl` on every target, list item and cell;
  - user origin, without `!important`: `li { text-align: start }`, which replaces the
    browser's `match-parent` and yields to any rule of the site.

`src/content.js` observes added nodes and character data on the whole document and
listens for `input`, batches what changed through `requestAnimationFrame`, and settles
the targets around each change. When a target's own direction moves, everything under
it is settled again. Forced mode keeps the observer for the list indents only.

## What changed from the first plan, and why

The first plan set `unicode-bidi: plaintext` on paragraphs through CSS and
`dir="auto"` on lists, tables and inputs. Both go by the first strong letter. Testing
on the real sites replaced that:

| First plan | Now | What showed it |
|---|---|---|
| Direction from the first letter | Direction from the share of right-to-left letters, set as an explicit `dir` | "JavaScript لغة برمجة…" came out left-to-right; on a site with an Arabic interface the extension made such text worse than the site had it |
| `dir="auto"` on every list, table and input | `dir` only where the text runs against the direction the element already has | An empty composer on a right-to-left site was flipped to the left |
| Items and cells each took their own direction | They follow their list or table | An item opening with "API" left its Arabic list; Latin and number cells broke the column |
| Every `ul` and `ol` was a text list | A list with an `aria-label` takes no direction | ChatGPT's transcript is an `ol`; forcing right-to-left moved the user's bubble across |
| `text-align: start !important` on all prose | The site's alignment is kept; cells of a right-to-left table are the exception | ChatGPT's centred footer line moved to the left |
| `li { text-align: start !important }` | The same rule under the user origin, without `!important` | Code review: an item the site aligned would have lost its alignment |
| Indent moved on every right-to-left list | Only on a marker list indented on the left alone | Layout lists without markers would have been padded |
| Observer for added nodes only | Added nodes, character data and `input` events | Needed once direction is computed rather than left to `dir="auto"` |
| Minimum Firefox 140 | 142 | `web-ext lint` warns about `data_collection_permissions` below it |
