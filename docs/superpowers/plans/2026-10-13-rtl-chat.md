# RTL Chat Implementation Plan

**Goal:** A Firefox MV3 extension that gives Arabic text the right direction on AI chat
sites, ready to load from `about:debugging` and to submit to AMO as a listed add-on.

**Architecture:** One pure module (`src/direction.js`) decides which CSS to apply and
which elements get a `dir` attribute. The content script wires it to the page and to
`storage.sync`; the background script injects the CSS with `scripting.insertCSS` (immune
to the page's CSP) and keeps one registered content script in step with the host
permissions the user granted for extra sites. The popup only writes settings and asks
for or drops a host permission.

**Tech stack:** WebExtension Manifest V3, plain JavaScript, no dependencies, no build
step. Tests: `node --test` for pure logic, headless Firefox for real bidi layout.

**Spec:** `docs/superpowers/specs/2026-10-13-rtl-chat-design.md`

## Global constraints

- Public name **RTL Chat**, licence **MIT**.
- No dependencies in `package.json`. `web-ext` runs through `npx` only.
- No network requests, no remote code, no data collection
  (`data_collection_permissions.required = ["none"]`).
- Permissions: `storage`, `scripting`, `activeTab`; `host_permissions` for the ten
  supported sites only; everything else through `optional_host_permissions`.
- Desktop Firefox only.
- Code and math stay LTR in every mode.
- Site chrome (navigation, menus, toolbars) is never restyled.
- Nothing is published to AMO and the repository stays private.

## Review focus

1. **A reply that starts in English and continues in Arabic** — each paragraph follows
   its own first strong character; one paragraph never drags the others.
2. **Streaming** — a list or table that arrives node by node ends up with the same
   direction as one that arrived whole.
3. **Switching off** — every `dir` the extension set is removed and an original `dir`
   the site had is put back.
4. **Code inside Arabic text** — inline `code` and `pre` blocks stay LTR, including
   inside an RTL list.
5. **Settings that are missing or malformed** in `storage.sync` — the extension falls
   back to auto mode, enabled, instead of throwing.

Each is pinned by a test in Task 1 or Task 2.

## File map

| File | Responsibility |
|---|---|
| `manifest.json` | Permissions, scripts, AMO keys |
| `src/sites.js` | The only place that knows site hosts and site-specific selectors |
| `src/direction.js` | Pure logic: settings, CSS text, target collection, apply and clear |
| `src/content.js` | Reads settings, asks for CSS, runs the MutationObserver |
| `src/background.js` | Inserts and removes CSS, syncs the custom-site content script |
| `src/popup/` | Per-site switch, mode choice, add or remove the current site |
| `_locales/{en,ar}/messages.json` | UI and listing strings |
| `icons/` | `icon.svg` source, `icon-48.png`, `icon-96.png` |
| `tests/unit.test.js` | Pure logic under `node --test` |
| `tests/browser/` | Fixture page, in-page assertions, headless Firefox runner |

## Task 1: Pure logic (`sites.js`, `direction.js`)

**Produces** (all on `globalThis.RTLChat`, also `module.exports` under Node):

- `SITES: Array<{id, name, hosts: string[], text: string[], input: string[], exclude: string[]}>`
- `GENERIC_SITE`, `findSite(hostname) -> site` (falls back to `GENERIC_SITE`)
- `builtinHosts() -> string[]`
- `normalizeSettings(raw) -> {mode: "auto"|"rtl", disabled: string[]}`
- `isEnabled(settings, hostname) -> boolean`
- `buildCss(site, mode) -> string`
- `originPattern(url) -> string|null` (`https://host/*`; `null` for non-http(s))
- `customOrigins(origins: string[]) -> string[]` (granted origins minus built-in hosts)

## Task 2: DOM half and real-layout test

**Produces:** `collectTargets(root, site) -> Element[]`, `applyAuto(el)`,
`applyAll(root, site)`, `clearAll(root)`.

- Targets: `ul, ol, table, blockquote`, text inputs, `textarea`, editable elements, plus
  the site's `input` selectors — skipped inside excluded chrome and inside code editors.
- `applyAuto` sets `dir="auto"`, remembers a previous `dir` in `data-rtl-chat-orig`, and
  marks the element with `data-rtl-chat`.
- `clearAll` restores or removes `dir` on every marked element.

Steps:

## Task 3: Extension wiring (`manifest.json`, `content.js`, `background.js`)

**Consumes:** everything from Tasks 1 and 2.

- `content.js`: guard against double injection; on start and on every
  `storage.onChanged` in `sync`, compute the state, send
  `{type: "rtl-chat:css", remove, insert}` to the background, then apply or clear and
  start or stop one `MutationObserver` on `document.documentElement`, batched through
  `requestAnimationFrame`.
- `background.js`: answer `rtl-chat:css` with `scripting.removeCSS` / `insertCSS` on the
  sender's tab and frame; on `runtime.onInstalled`, `runtime.onStartup`,
  `permissions.onAdded` and `permissions.onRemoved`, register, update or unregister the
  content script `rtl-chat-custom` for `customOrigins(...)`; on `onAdded`, also inject
  into tabs already open on the new origins.
- `manifest.json` per Global constraints, gecko id `rtl-chat@musaad-sharikh`.

Steps:

- [ ] Write the three files and the icons.
- [ ] `npx web-ext lint` reports no errors.
- [ ] Commit.

## Task 4: Popup and locales

- Shows the current host and whether it is supported, added by the user, or not covered.
- Switch: enabled on this site (writes `disabled`).
- Mode: auto or force RTL (writes `mode`).
- Not covered: "Enable on this site" calls `permissions.request` straight from the click
  handler. Added by the user: "Remove this site" calls `permissions.remove`.
- Every string through `i18n`; the popup's own `dir` comes from `@@bidi_dir`.
